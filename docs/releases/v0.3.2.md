**Phones Windows won't stream from are no longer hidden.** A paired phone that Windows offers no
audio from now shows in the dock and in settings with the reason, for example *Windows doesn't
offer its audio* or *Paired over Bluetooth LE only*, and what to try. Before, it simply didn't
appear, which looked like BudsBridge had missed it.

This came from the first real test: an OPPO A83 plays through the laptop fine, while a Pixel 7 on
the same laptop never started, and after re-pairing Windows stopped offering it at all.

### Download

| File | What it is |
|---|---|
| `BudsBridge.exe` | Single file, no installer. Download and open it |
| `BudsBridge-0.3.2-windows-x64-setup.exe` | Installer for your user only: Start menu entry and uninstaller, no admin prompt |
| `SHA256SUMS.txt` | Checksums for both files |

The build isn't code-signed, so SmartScreen warns once: **More info → Run anyway**.

### New

- **Copy diagnostics** (settings → Troubleshooting) copies what BudsBridge and Windows see: your
  buds and phones, every paired Bluetooth device, and which Bluetooth services Windows set up for
  each phone. Paste it into a bug report. It includes device names and Bluetooth addresses.
- When Windows' Bluetooth driver fails to start phone audio (error `0x8007001f`), the message now
  says so plainly instead of showing only the code.

### Updating

Opening the new `BudsBridge.exe` while 0.3.1 runs switches to the new one by itself. From 0.3.0 or
older, quit the old copy first (right-click the tray icon → **Quit**).
