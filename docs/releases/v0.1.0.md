**First preview of BudsBridge, the MVP.** It builds and passes every automated test on Windows,
but it has **not been tested with real earbuds yet**, so it is marked as a pre-release.
If you try it, the [hardware checklist](https://github.com/shakaibarsalan/BudsBridge/blob/main/docs/HARDWARE_TESTING.md)
says what to check and what to report.

### Download

| File | What it is |
|---|---|
| `BudsBridge.exe` | Single file, no installer. Download and open it |
| `BudsBridge-0.1.0-windows-x64-setup.exe` | Installer for your user only: Start menu entry and uninstaller, no admin prompt |
| `SHA256SUMS.txt` | Checksums for both files |

Requirements: Windows 11, and buds paired once in **Settings → Bluetooth & devices**. Nothing else
needs to be installed: Windows 11 already has the WebView2 runtime the app uses. Windows 10 should
work too (without the Mica backdrop) if WebView2 is installed, but it hasn't been tried.

The build is not code-signed, so SmartScreen shows "Windows protected your PC" the first time:
**More info → Run anyway**.

### What's in it

- Paired Bluetooth audio devices in one list, with one-click **Connect** / **Disconnect**
- Tray icon with live status (filled when connected) and a menu to toggle devices
- Global hotkey, `Ctrl+Alt+B` by default, to toggle your chosen device
- Auto-reconnect with back-off after an unexpected drop; never after a manual disconnect
- Start with Windows, minimized to the tray
- Mica backdrop and system light/dark theme on Windows 11

### Known limits

- Software can't add multipoint. Buds that are busy with your phone may ignore the laptop until the phone lets go.
- Connect/disconnect relies on the Bluetooth driver supporting `KSPROPSETID_BtAudio`. Most do, but some vendor drivers may not.
- The UI is the functional MVP layout; the final design comes in a later release.
